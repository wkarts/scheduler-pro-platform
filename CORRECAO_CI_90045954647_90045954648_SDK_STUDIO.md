# Correção CI — runs 90045954647 / 90045954648 + SDK & Template Studio

## Falhas confirmadas nos logs

### API / Ruff

- `tenant_management.py`: `APIError` era utilizado sem import (`F821`, 3 ocorrências).
- `experience_service.py`: `hashlib` permaneceu importado sem uso (`F401`).

Correção: import explícito de `APIError` e remoção do import órfão.

### Web / TypeScript

- `PublicSitePage.vue`: referências nullable de `landing` e `catalog` no template (`TS18047`).
- `TenantConsole.vue`: handler `openBlockedPeriod` recebia `MouseEvent` no botão de criação (`TS2345`).
- `publicAnalytics.ts`: chamada opcional de `window.fbq` podia ser `undefined` (`TS2722`).

Correção: computed views não nulas para renderização, chamada explícita `openBlockedPeriod()`, e inicialização do Meta Pixel pela função local `fbq` antes de expô-la em `window`.

### PWA contract

O manifest 2.4.0 usa `/?source=pwa`, mas o validador ainda exigia `/#dashboard`.

Correção: contrato atualizado para `/?source=pwa` e validação adicional do tratamento de `source=pwa` em `App.vue`.

### Integration

`tests/test_avb_240_experience_contract.py` usava `Path(...).parents[3]`. Na imagem isolada da API (`/app/tests/...`) esse nível não existe e a coleta terminava com `IndexError: 3`.

Correção: a raiz da API agora é calculada por `parents[1]`; fontes Web/Admin são opcionais e os contratos visuais são ignorados apenas quando essas árvores não fazem parte da imagem isolada.

## SDK & Template Studio no Control Plane

Foi adicionado ao Control Plane o módulo permanente **SDK & Template Studio**, protegido por `templates.manage`.

O administrador pode, de qualquer máquina:

- ler/copiar o padrão mestre para IA;
- ler/copiar a documentação do Template Runtime SDK v1;
- baixar o Experience Contract v2;
- baixar Bindings v1 e Theme Tokens v1;
- baixar o guia de migração v1 → v2;
- baixar o exemplo enriquecido Experience Package v2;
- baixar o pacote NPM/TGZ do ARGWS Visual Builder 2.4.0.

API:

- `GET /api/v1/platform/templates/developer-kit`
- `GET /api/v1/platform/templates/developer-kit/artifacts/{artifact}`

Os artefatos são embarcados em `apps/api/resources/avb-template-kit/`, portanto não dependem da máquina local do administrador.
